# ShyOS

ShyOS is a minimal xv6-like operating system for ShyISA, written in ShyC with small Shy assembly entry, trap, scheduler, and syscall-wrapper pieces. It builds a kernel image, embeds a read-only in-memory file system, boots `init`, and runs a shell that can execute a busybox-style set of user programs.

## Architecture

- Kernel entry starts at `kernel/entry.shy`, sets the kernel stack, and calls `kmain`.
- Memory isolation is segment-based. Each user process receives a 1 MiB segment starting in the user segment region (256 KiB with `SHYOS_SMALL`). User images declare `#![mem(256K)]` and `#![stack(...)]`; the kernel reads those linked-image hints during `exec`.
- The process table in `kernel/proc.shyc` has 16 slots (12 with `SHYOS_SMALL`) and tracks process state, pid, parent pid, kernel stack, user segment base, size, heap break, stack base, exit status, sleep channel, and killed flag.
- The scheduler is round-robin over runnable non-idle processes. An idle process with pid 0 yields when no user process is runnable.
- Trap entry and context save/restore live in `kernel/trapentry.shy`, `kernel/ctx.shy`, and `kernel/scheduler.shy`. Syscall dispatch is in `kernel/trap.shyc`.
- Timer traps mark the current process runnable and reload the timer.
- The file system is a read-only in-memory table generated by `tools/bin2shy.py` into `target/fs/fsdata.c`. It embeds user `.sfs` binaries and `test.txt`; identical binaries (the busybox applets) are embedded once and shared by all of their names. The kernel also keeps a small mutable directory table so `mkdir` and `rm` work.
- `init` starts `/sh`, waits for it, and restarts it unless the shell exits with status 2 for input EOF.

## User Segment Layout

All user addresses are segment-relative virtual addresses. The scheduler loads
`segs = p->segbase` and `sege = p->segbase + USER_SEG_SIZE`, so the same virtual
layout is backed by a different physical segment for each process.

- `0x00000100`: user entry point (`_start`), with linked text/data following it.
- `0x000ef000..0x000ef07f`: exec argument buffer (`USER_ARG_ADDR`, `USER_ARG_MAX`). With `SHYOS_SMALL` it sits at `0x0002f000`.
- Heap grows upward from the end of the loaded image, managed by `sbrk`.
- `USER_STACK_BASE(stack_hint)..0x000fff00`: user stack area. ShyC stack frames grow upward, so the kernel initializes `sp` to the low end of the declared stack reservation.
- `0x000fff00..0x000fffff`: guard gap below the segment ceiling.

Current user programs declare their own stack size; `stackbig` declares 16 KiB and is used by the integration test to verify that the kernel does not rely on a fixed stack location.

## Build

From the repository root:

```sh
make -C projects/os build
make -C projects/os run
make -C projects/os test
```

The root Makefile also provides:

```sh
make os-build
make os-run
```

### Small-memory build

`make small_mem` compiles the same sources with `-DSHYOS_SMALL`: user segments
shrink to 256 KiB, the process table to 12 slots, and the heap and scheduler
stack move below 1 MiB so the kernel runs in 4 MiB of RAM.

```sh
make -C projects/os small_mem
make -C projects/os small_run      # shyemu target/small/kernel.sfs --mem 4M
```

The image is written to `target/small/kernel.sfs`; the default `target/` build
is untouched.

## Run

Run the OS through the root Makefile:

```sh
make os-run
```

Run the emulator directly:

```sh
cargo run -q -p emu -- projects/os/target/kernel.sfs --mem 128M
```

Scripted shell input also works, but note that the shell does not echo input
itself; in a pipe the output shows the prompt followed by the command result:

```sh
printf "echo hello\ncat test.txt\nexit\n" | make os-run
```

Output:

```
ShyOS boot
$ hello
$ hello world
$ $
```

## User Shell and Applets

`/sh` is a small shell that reads commands from fd 0, parses a command line into
arguments, and supports:

- Simple commands: `echo hello`, `cat test.txt`, `ls`, etc.
- Pipelines: `echo hello | cat`.
- I/O redirection: `echo hello > file.txt`, `cat < file.txt`.
- Built-in `exit`.

The shell is implemented inside the same busybox-style multi-call binary as the
other applets. The binary is linked once as `target/user/busybox.sfs` and then
installed under the names `sh`, `echo`, `cat`, `ls`, `mkdir`, `rm`, `pwd`, `wc`,
`grep`, `ps`, `kill`, and `exit`. Each name selects an applet via an explicit
if-else dispatch chain (ShyC has no function pointers).

## Tests

`make -C projects/os test` builds the kernel, runs the emulator with a
scripted shell input, and checks the transcript contains `ShyOS boot`, the
prompted command results (`$ hello`, `$ hello world`), and the final restarted
shell prompt. It also runs the `p7malloc` user test and requires the emulator
exit code to be 0.
- The emulator exit code is 0.

```sh
make -C projects/os test
```

## Directory Structure

- `kernel/`: kernel C and assembly sources.
- `user/`: user programs, syscall wrappers, and user library.
- `tools/`: build helper scripts, including the file-system embedder.
- `test.txt`: sample file embedded into the in-memory file system.
- `target/`: generated build output, including user binaries, generated FS data, and `kernel.sfs`.

## System Calls

| Number | Name | Description |
| --- | --- | --- |
| 1 | `fork` | Allocate a child process, copy the parent user segment, and return the child pid in the parent and 0 in the child. |
| 2 | `yield` | Mark the current process runnable and enter the scheduler. |
| 3 | `getpid` | Return the current process id. |
| 4 | `exit` | Mark the current process zombie, store its exit status, wake a waiting parent, and halt the emulator when no user work remains. |
| 5 | `write` | Write a user buffer to fd 1, the console. |
| 6 | `read` | Read from fd 0, the console, or from an opened embedded file descriptor. |
| 7 | `exec` | Load an embedded program into the current user segment and reset the user context. |
| 8 | `wait` | Reap a zombie child and optionally copy its exit status to user memory. Blocks while children are still running and returns -1 when there are no children. |
| 9 | `open` | Open a file from the embedded read-only file system. File descriptors start at 3. |
| 10 | `close` | Close an embedded-file descriptor. |
| 11 | `kill` | Mark a process killed and wake it if it is sleeping so it exits before returning to user mode. |
| 12 | `sleep` | Block the current process on a nonzero integer channel. |
| 13 | `wakeup` | Wake all processes sleeping on a matching nonzero integer channel. |
| 15 | `pipe` | Create a unidirectional pipe and return two file descriptors. |
| 16 | `dup2` | Duplicate a file descriptor onto another descriptor. |
| 17 | `create` | Create a new file in the mutable directory table. |
| 18 | `dirent` | Read a directory entry by index. |
| 19 | `mkdir` | Create a directory entry in the mutable directory table. |
| 20 | `rm` | Remove a directory entry from the mutable directory table. |
| 21 | `psline` | Format a process-table entry for `ps`. |
| 22 | `sbrk` | Move the per-process heap break and return the old break. |

## Memory Allocator

User-space `malloc` and `free` live in `user/ulib.shyc`. The current implementation
uses a simple bump allocator: `malloc(n)` 4-byte aligns the request, calls the
`sbrk` syscall, and returns the old break. `free` is a no-op that accepts `NULL`.

The kernel's `sbrk` handler in `kernel/proc.shyc` keeps `heap_base` as the lower
bound (the loaded image size) and `stack_base` as the upper bound. It rejects
requests that would move the break into the stack region or beyond the 1 MiB
segment.

## Constraints

- ShyC currently has no function pointers, so dispatch is explicit rather than table-driven in several places.
- User syscall wrappers are raw Shy assembly in `user/usys.shy`.
- Trap entry, context save/restore, and scheduler return paths are handwritten assembly.
- The code avoids ShyC patterns that are known to stress current 64-bit loop code generation; loops and memory copies stay simple and explicit.
- The embedded file system is read-only, but a small kernel-side mutable directory table supports `mkdir`/`rm`/`ls`.
